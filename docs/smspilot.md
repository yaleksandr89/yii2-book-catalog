# SMSPilot

При создании новой книги приложение уведомляет по SMS гостей, подписанных на одного из её авторов. Интеграция работает только в тестовом режиме SMSPilot: запросы проходят через сервис, но реальная доставка оператору не выполняется.

## Как устроена отправка

```text
BookService
    ↓
SmsSenderInterface
    ↓
SmsPilotSender
    ↓
SMSPilot
```

[`BookService`](../services/BookService.php) зависит от небольшого интерфейса [`SmsSenderInterface`](../integrations/SmsSenderInterface.php), а работа с конкретным внешним сервисом находится в [`SmsPilotSender`](../integrations/smspilot/SmsPilotSender.php).

[`SmsPilotSendResponse`](../integrations/smspilot/SmsPilotSendResponse.php) проверяет, что успешный ответ SMSPilot имеет ожидаемую структуру. Ключ сервиса передаётся через конфигурацию приложения и не хранится в исходном коде.

В `SmsPilotSender` для каждого запроса принудительно передаётся `test=1`. Также задан небольшой сетевой тайм-аут и отключено журналирование содержимого HTTP-ответа.

## Когда отправляется SMS

Отправка не входит в транзакцию сохранения книги.

Порядок действий следующий:

1. сохраняется изображение;
2. книга и связи с авторами записываются в базу данных;
3. транзакция успешно завершается;
4. только после этого выбираются подписчики и начинаются запросы к SMSPilot.

Благодаря этому недоступность SMSPilot не может отменить уже созданную книгу.

Если внешний сервис возвращает ошибку для одного номера, [`BookService`](../services/BookService.php) записывает предупреждение и продолжает обработку остальных получателей.

## Как выбираются получатели

Получатели выбираются одним агрегатным запросом по номерам телефонов.

Если один номер подписан на нескольких авторов новой книги, он всё равно появляется в результате один раз и получает не более одной попытки отправки. Это одновременно исключает дублирование уведомлений и не создаёт отдельный запрос к базе для каждого автора.

Порядок номеров фиксирован сортировкой, поэтому обработка получателей остаётся предсказуемой.

## Почему сообщение было сокращено

Первая рабочая версия отправляла текст с названием книги. Функционально это работало: при ручной проверке SMSPilot вернул HTTP 200 и успешный тестовый статус `0`. В ответе эмулятора были, в частности, значения:

```text
server_id = 10000
status    = 0
price     = 19.74
cost      = 19.74
balance   = 60.89
```

Реальной доставки не было — запрос выполнялся с `test=1`.

На этом этапе стало видно, что длинное кириллическое название книги делает текст составным SMS. Длина названия задаётся пользователем, поэтому количество сегментов и рассчитанная эмулятором стоимость могли расти вместе с ним.

После этого название книги из уведомления убрали и оставили два ограниченных варианта:

```text
Новая книга у автора: <имя автора>.
```

Если подходящих авторов несколько:

```text
Новая книга у авторов из ваших подписок.
```

Повторная ручная проверка дала такие результаты:

| Сценарий | Попыток отправки на номер | Статус SMSPilot | `price` | `cost` |
| --- | ---: | ---: | ---: | ---: |
| Один подходящий автор | 1 | 0 | 9.87 | 9.87 |
| Два подходящих автора, на обоих есть подписка | 1 | 0 | 9.87 | 9.87 |

То есть в проверенном сценарии рассчитанная эмулятором стоимость уменьшилась с `19.74` до `9.87` — ровно в два раза. Это результат конкретной проверки в тестовом режиме, а не заявление о тарифе SMSPilot или о стоимости реальной доставки.

Вторая проверка одновременно подтвердила дедупликацию: даже при подписке одного номера на двух авторов новой книги выполнялась одна попытка отправки.

## Обработка ошибок

[`SmsPilotSender`](../integrations/smspilot/SmsPilotSender.php) преобразует сетевые ошибки, неуспешный HTTP-ответ, некорректный JSON и отказ самого SMSPilot в `RuntimeException` с безопасным сообщением.

[`BookService`](../services/BookService.php) перехватывает такую ошибку уже после сохранения книги. В журнал попадает короткое предупреждение без ключа API и без исходного ответа провайдера; следующие получатели продолжают обрабатываться.

Таким образом, сбой уведомления остаётся ошибкой внешней интеграции и не повреждает состояние каталога.

## Если отправок станет много

Сейчас запросы к SMSPilot выполняются последовательно в том же HTTP-запросе, в котором создаётся книга. Для небольшого тестового приложения это позволяет обойтись без отдельной инфраструктуры.

При росте нагрузки отправку лучше вынести в очередь фоновых задач. В Yii2 для этого можно использовать, например, [`yiisoft/yii2-queue`](https://github.com/yiisoft/yii2-queue). Если дополнительно нужны гарантии повторной доставки, состояние исходящих уведомлений стоит хранить отдельно в базе данных, а отправку выполнять независимым обработчиком.

При большом количестве получателей также имеет смысл рассматривать пакетную отправку на стороне SMS-провайдера, чтобы уменьшить число отдельных HTTP-запросов.
