# Архитектура

Проект собран вокруг стандартных возможностей Yii2 без дополнительных слоёв ради самих слоёв. ActiveRecord используется для обычной работы с данными, модели форм — для проверки пользовательского ввода, а составные операции вынесены туда, где действительно требуется отдельная граница ответственности.

## Общая схема

```text
HTTP-запрос
    ↓
контроллер
    ↓
модель формы
    ↓
сервис / ActiveRecord / отдельный запрос отчёта
    ↓
MySQL
```

Например, [`BookController`](../controllers/BookController.php) принимает запрос, проверяет права доступа, получает загруженный файл и запускает валидацию. [`BookForm`](../models/BookForm.php) проверяет поля книги, выбранных авторов и изображение. После успешной проверки контроллер передаёт изменение книги в [`BookService`](../services/BookService.php).

Так контроллер не занимается транзакциями, файловой системой или отправкой SMS.

## Данные и связи

Основные модели:

- [`Book`](../models/Book.php) — книга;
- [`Author`](../models/Author.php) — автор;
- [`Subscription`](../models/Subscription.php) — подписка номера телефона на автора;
- [`User`](../models/User.php) — пользователь, который может изменять каталог.

Книга может иметь нескольких авторов, а автор — несколько книг. Связь хранится в таблице `book_author`.

Структура базы задаётся [миграциями](../migrations/). Внешние ключи защищают связи между таблицами, повторное добавление одной и той же пары «книга — автор» запрещено уникальным индексом, а для года выпуска книги есть отдельный индекс, используемый отчётом.

При выводе списка книг авторы загружаются заранее через `with('authors')`, поэтому для каждой книги не выполняется отдельный запрос к базе.

## Сохранение книги

[`BookService`](../services/BookService.php) нужен потому, что изменение книги состоит сразу из нескольких действий: сохранить саму книгу, обновить список авторов, обработать изображение и при создании уведомить подписчиков.

При создании:

1. новое изображение сохраняется под сгенерированным именем;
2. книга и её связи с авторами записываются внутри одной транзакции;
3. при ошибке транзакция откатывается, а новый файл удаляется;
4. после успешного завершения транзакции начинается отправка уведомлений.

При обновлении старое изображение остаётся на месте, если новый файл не загружен. Если изображение заменяется, старый файл удаляется только после успешного сохранения нового состояния книги.

При удалении сначала фиксируется удаление записи из базы данных и только после этого удаляется файл изображения.

Так файловая система не должна оказаться в состоянии, когда рабочее изображение удалено, а изменение книги в базе не сохранилось.

## Отчёт Top-10

Форма [`TopAuthorsReportForm`](../models/TopAuthorsReportForm.php) проверяет выбранный год, а [`TopAuthorsQuery`](../models/TopAuthorsQuery.php) строит сам отчёт.

Подсчёт выполняется одним агрегатным запросом в MySQL: книги фильтруются по году, группируются по авторам, после чего выбираются первые десять результатов. При одинаковом количестве книг порядок остаётся предсказуемым за счёт дополнительной сортировки по имени и идентификатору автора.

Запрос вынесен из контроллера отдельно, потому что это самостоятельная операция чтения с агрегацией, а не обычный поиск ActiveRecord-модели.

## Проверка данных и доступ

Пользовательский ввод проверяется на сервере. Например, [`BookForm`](../models/BookForm.php) проверяет обязательные поля, год выпуска, существование выбранных авторов и загружаемое изображение: допустимые расширения, MIME-тип и размер до 5 МиБ.

Для действий, изменяющих каталог, контроллеры используют `AccessControl`; удаление разрешено только методом POST через `VerbFilter`. В обычных веб-формах действует CSRF-защита Yii.

Запросы к базе строятся средствами ActiveRecord, Query Builder и параметризованных условий Yii — пользовательские значения не подставляются в SQL строковой конкатенацией.

Секреты, включая `SMSPILOT_API_KEY`, читаются из окружения и конфигурации приложения.

## Что сознательно не усложнялось

ActiveRecord не обёрнут отдельным репозиторием для каждой модели. В этом приложении такой слой в основном повторял бы уже имеющиеся возможности Yii и не давал бы полезной изоляции.

Отправка SMS выполняется синхронно после сохранения книги. При заметной нагрузке её лучше вынести в очередь фоновых задач; для Yii2 существует отдельное расширение [`yiisoft/yii2-queue`](https://github.com/yiisoft/yii2-queue). В рамках тестового приложения очередь, отдельный обработчик задач и инфраструктура для него не добавлялись.

Приложение остаётся серверным Yii2 Web: отдельный REST API и SPA не создавались, поскольку они не нужны для поставленной задачи.
